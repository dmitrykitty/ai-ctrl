# Architecture

`plan.md` remains the approved design. T01 foundation and T02 launcher/isolation are implemented; T03 is the next application gateway milestone.

The Python host CLI alone controls Docker. Adapters render agent configuration; runtime owns workspace validation, identity, container/proxy lifecycle, limits, signal/deadline handling, and cleanup. Session metadata reuses `AgentSession` and records container name/ID and deadline in `ManagedSession`. Every ephemeral container, network, and CA volume carries its session label. A stopped, unmounted reservation shares the authentication helper's fixed name to prevent concurrent native state operations. No container receives the Docker socket.

T02 topology is Claude → enforcing mitmproxy → exact allowed provider destinations. The Claude container joins only an internal IPv4 network. Proxy alone joins upstream. Default-deny bootstrap permits exact infrastructure TCP sockets and required TCP loopback/replies; direct internet, DNS, UDP/QUIC, IPv6, host and sibling bypasses fail. Proxy admission occurs before HTTP/CONNECT forwarding and before server connection; resolved public addresses are checked and used numerically. Trusted synthetic destinations are explicit host configuration, never caller-supplied upstream URLs.

`EGRESS_ONLY` preserves native Anthropic endpoints, configured HTTP/HTTPS proxy, and subscription state. `APPLICATION_GATEWAY` retains future native Anthropic routing and internal session identity; the launcher refuses that mode until infrastructure exists. Provider TLS in T02 is explicitly opaque CONNECT: destination/port enforcement only, no body inspection. Public CA export/trust is prepared; CA private material remains exclusively on the proxy.

Claude mounts one selected workspace, read-only public CA, and `aictrl-claude-state` at `/home/dev/.claude`. Enterprise credentials, host agent/configuration directories, policy/audit stores and Docker socket remain outside. Unsafe control/credential workspaces are rejected. Trusted root setup prepares container home/state without following workspace links, then drops to positive host UID/GID, no supplementary groups, all capability sets empty and no-new-privileges. State may safely change owner between login UID 501 and runtime host identity; workspace ownership is untouched. Setup-only DAC_OVERRIDE permits that state transition, while KILL permits trusted Docker init to forward signals across the UID transition; native Claude retains neither.

Native authentication status runs offline against read-only dedicated state at its existing numeric owner. Unauthenticated/operationally unavailable state refuses normal launch. Login is separate and idempotent. Native UI preparation changes only the onboarding preference inside provider configuration; it never opens credential files or automatically trusts the workspace.

CPU/memory/PID limits are enforced by Docker/cgroups; one monotonic host deadline spans session preparation and execution. Host signals target label-verified session containers. Cleanup reaps the Compose client and deletes ephemeral infrastructure/CA material, preserving provider state and workspace. Future restrict/terminate hooks operate only on the owned session.

Contract schema version remains 1: serialized shared contracts were not changed. Routing mode belongs to adapter/runtime configuration, and lifecycle enforcement remains outside data models. The future modular monolith separates gateway, policy, guards, governance, reporting and dashboard; SQLite durability begins in its designated milestone. T02 adds no application gateway, central policy, guards, MCP semantics, budgets, audit pipeline or dashboard.
